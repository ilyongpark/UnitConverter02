## 1. 개요

사용자가 입력한 길이(`단위:값`)를 기반으로, 해당 값을 **지원 단위 전체**로 변환해 CLI에 출력하는 프로그램.

이번 세션(UnitConverter_02d)의 목표는 기능 전체 구현이 아니라, **모호한 스펙을 PRD에서 명시하고 테스트로 고정한 뒤, 요구사항·테스트·코드를 REQ 단위로 추적 가능하게** 만드는 것이다.

## 4. 기능 요구사항

### REQ-IN-01 — 입력

- **형식:** `{unit}:{value}` (콜론 1개로 분리)
- **예시:** `meter:2.5`
- **프롬프트:** `Insert value for converting (ex: meter:2.5): `
- **단위명:** 소문자 `meter`, `feet`, `yard` 만 지원

### REQ-CONV-01~03 — 변환

모든 변환은 **meter를 기준 단위**로 환산한 뒤 다른 단위로 변환한다.

| 변환율 | 값 |
|--------|-----|
| 1 meter | 3.28084 feet |
| 1 meter | 1.09361 yard |

- feet ↔ yard 비율은 meter 기준으로 계산한다.
- 입력 단위가 meter/feet/yard 중 하나이면, **나머지 두 단위 + meter** 결과를 모두 출력한다.

### REQ-OUT-01 — 출력

#### 4.1 출력 순서

입력 단위를 제외한 지원 단위를 아래 순서로 출력한다. (입력이 meter이면 feet → yard 순)

1. meter (입력이 meter가 아닐 때)
2. feet (입력이 feet가 아닐 때)
3. yard (입력이 yard가 아닐 때)

> 현재 `UnitConverter.py`는 입력 단위 포함 3줄을 출력한다. 이번 세션은 **기존 3줄 출력 형식을 유지**한다.

#### 4.2 출력 형식 (한 줄)

```
{원본값} {원본단위} = {변환값} {대상단위}
```

- `{원본값}`: 사용자가 입력한 숫자 문자열을 파싱한 값 (반올림 없음, 예: `2.5`)
- `{변환값}`: 아래 반올림 규칙 적용

#### 4.3 반올림 규칙 (Mom Test에서 명시화)

| 규칙 | 내용 |
|------|------|
| 자릿수 | 소수점 **1자리** |
| 방식 | **반올림** (round half up) |
| 표시 | 불필요한 trailing zero 제거 가능 (예: `8.0` → `8.0` 허용) |

**검증 예시 (필수 통과):**

| 입력 | 기대 출력 (일부) |
|------|------------------|
| `meter:2.5` | `2.5 meter = 8.2 feet` |
| `meter:2.5` | `2.5 meter = 2.7 yard` |

> 내부 계산은 전체 정밀도로 수행하고, **출력 직전**에만 1자리 반올림을 적용한다.

### REQ-VAL-01 — 잘못된 형식

- 콜론(`:`)이 없는 입력
- **메시지:** `Invalid format. Use unit:value (ex: meter:2.5)`
- 프로그램 종료 (추가 출력 없음)

### REQ-VAL-02 — 음수

- 값이 0 미만인 경우
- **메시지:** `Invalid value: negative numbers are not allowed` (또는 동등한 명확한 문구)
- 프로그램 종료

### REQ-VAL-03 — 숫자 파싱 실패

- `:` 뒤가 유효한 실수가 아닌 경우
- **메시지:** `Invalid number: {value_str}`
- 프로그램 종료

### REQ-VAL-04 — 미지원 단위

- `meter`, `feet`, `yard` 외 단위
- **메시지:** `Unknown unit: {unit}`
- 프로그램 종료

## 5. 품질 요구사항

### REQ-QUAL-01 — 테스트 선행

- README 예시(REQ-OUT-01) 및 변환(REQ-CONV) 테스트를 **구조 변경 전**에 작성·통과시킨다.
- 리팩터링 후에도 동일 테스트로 회귀를 검출할 수 있어야 한다.

### REQ-QUAL-02 — 최소 구조 변경

- OCP/SRP는 **테스트 GREEN 이후** 최소 범위에서만 적용한다.
- 단위 추가 시 기존 코드 변경을 최소화하는 방향을 유지하되, 이번 세션에서 신규 단위 추가는 범위 외이다.

### REQ-TRACE-01 — 추적 가능성

- `tests/REQ_TRACE.md`에 REQ ID ↔ 테스트 파일/함수명 ↔ 코드 위치 매핑을 유지한다.
- 테스트 docstring에 `REQ-` ID와 본 PRD 절 번호를 기록한다.
